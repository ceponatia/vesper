# Narrator model profiles and test bench

Status: active (replanned 2026-08-17 after the first bench use exposed a shared-prompt mismatch)

Outcome: The owner can choose a narration-tuned model and hear the richer,
scene-like prose it was selected for, while proven narrators and every
non-narrator agent continue to behave exactly as they do now.

## Why

The first slice proved that eleven roleplay and low-refusal models are reachable
and selectable. It did not prove that Vesper asks them to do the job they were
built for.

Character chat currently chooses one response shape for the whole lane. Every
selected model receives the chat lane's `aggressive_concise` guidance: answer in
as few sentences as needed, make at most one forward move, and stop. That shape
was selected from an earlier comparison in which GLM 5.2 benefited from tighter
replies. The same comparison found that Aion preferred the more immersive shape
and that the immersive arm produced the stronger voice. Applying the GLM-shaped
ruling to Magnum, Euryale, Cydonia, Rocinante and the rest turns their obedience
into the failure now visible on screen: short replies that are technically on
beat but do not feel like scenes.

This is not an output cutoff. The narrator streams until the model stops. The
prompt itself repeatedly rewards the shortest safe answer: no unrelated topic,
no stacked moves, no repeated setting or appearance, tightly gated sensory
detail, and no customary length. Those safeguards protect state and player
agency, but they currently leave a narration-tuned model little room to spend its
strength on physical reaction, subtext, atmosphere and character voice.

The successor lane has the same underlying mismatch because it reuses the same
craft block and the same lane-wide shape. It also has a separate wiring gap: the
ordinary chat route carries the chosen narrator into the legacy pipeline, while
the successor fork currently drops that choice and falls back to Aion 3.0.
Before the bench can produce a trustworthy verdict, one resolved narrator model
and one model-specific presentation profile must govern both the prompt and the
call that answers it.

## What the owner gets

- **The proven narrators stay proven.** Aion 2.0, Aion 3.0, Aion 3.0 Mini,
  DeepSeek 4 Flash, GLM 5.2, Gemini 3.5 Flash and Grok 4.5 keep their current
  prompt shape, temperature, reasoning and provider behavior. Merely adding the
  profile system changes none of their generated bytes or call options.
- **Narration-tuned models get an opt-in scene profile.** Exact models selected
  for the roleplay bench may use a new immersive profile that asks for a complete
  lived beat rather than the shortest valid chat answer. The profile keeps one
  forward story move as the ceiling while making clear that reaction,
  description, subtext and the landing of that move are texture, not extra plot
  moves.
- **Richness without padding or player theft.** A normal beat may use a few rich
  paragraphs when the established scene offers real material. A bare greeting
  can still be short. No minimum length is imposed, and every existing rule about
  committed state, physical continuity, perception, speaker attribution and
  player agency remains binding.
- **The selected narrator reaches both narrator lanes.** A successor chat uses
  the same curated narrator choice as an ordinary character chat. No saved
  choice still means Aion 3.0, preserving today's default.
- **A fair model comparison.** Prompt shape is tested before sampling settings,
  so a model is not judged while carrying another model's prompt policy. Any
  later temperature or provider override is exact-model evidence, never a family
  guess.
- **Agents remain isolated.** The scene composer, state agents, intake agents,
  post-turn agents and image models keep their own model lists and settings. The
  successor deliberator is explicitly frozen on its present Aion 3.0 behavior
  under an agent-owned policy so changing the narrator can no longer move it by
  accident.

## Boundaries

### In scope

- Both prose-producing narrator lanes: ordinary character chat and successor
  narration, including the successor's co-present and solo renderers.
- One exact narrator-model identity resolved before prompt construction, then
  reused for prompt profile, call options, retries, retakes and observability.
- A new `immersive_roleplay` presentation profile for specifically listed
  narration-tuned models.
- Model-specific sampling experiments only after the prompt-profile comparison
  has identified finalists.
- A recorded, blinded comparison using fixed Vesper scenes and independent
  history per arm.
- Preserving the successor deliberator's current effective model and settings
  while removing its dependency on narrator selection.

### Non-goals

- **No default-model change in this plan's build slices.** Aion 3.0 remains the
  character-chat and successor fallback until the final evidence ruling.
- **No broad prompt rewrite.** The camera, player-agency, physical-state,
  perception, mature-content, attribution and continuity laws remain shared and
  unchanged. The work changes how much room a model gets to render one lawful
  beat, not what the world permits.
- **No hard paragraph or token floor.** Longer output is not automatically better,
  and padding is not a substitute for scene presence.
- **No automatic model-card settings.** Published temperature, top-p, top-k and
  repetition recommendations are hypotheses to test, not production defaults.
- **No narrator policy inside generic generation helpers.** A model used for a
  composer, classifier, state agent or deliberator receives that task's explicit
  policy, never the policy it would receive as a narrator.
- **No self-hosted deployment.** Replicate remains an escape hatch only if an
  unavailable set of weights later wins on evidence. A second *hosted* provider is
  no longer a non-goal: the owner added a Featherless account on 2026-08-17, and
  narration is the one leg allowed to use it. Every other model list — agents, the
  scene composer, embeddings, vision — stays on the single existing provider.
- **No context-window invention.** A 32K model that overflows a long Vesper chat is
  not silently truncated or promoted; it must either pass a separately reviewed
  context-fit design or remain a limited test option.

## Slices

- **Slice 1 — the bench is pickable.** Status: complete — 2026-08-17. Eleven
  narration-tuned and control models are available from the narrator menu, and
  the alternative providers have recorded probe evidence.
- **Slice 1b — the bench can hold models from a second provider.** Status: built
  2026-08-17 — awaiting an owner run of the first Featherless row on the deployed
  app. The narrator menu can now list a model served by Featherless as well as by
  OpenRouter, chosen and stored the same way, with the rest of the app's models
  untouched. A pick whose provider has no configured key quietly uses the lane's
  usual narrator instead of failing the turn. The first such row is an uncensored
  Qwen3.6 27B merge; whether it is usable in the chat lane is an open question
  below, not a settled result.
- **Slice 2 — one narrator identity and profile governs each call.** Status: next.
  Resolve the curated model once before building either narrator prompt, carry
  that same resolved identity through generation and retry, and record the
  effective profile with the reply. Unprofiled models fall through to the exact
  current lane behavior. The successor route begins honoring the chosen narrator,
  with Aion 3.0 still the no-choice fallback.
- **Slice 3 — narration-tuned models receive an immersive scene profile.** Status:
  queued. Add one bounded profile that preserves every state and agency law but
  distinguishes plot advancement from the prose used to inhabit a single beat.
  Apply it only to exact roleplay/prose candidates in character chat; the proven
  models and the two control rows stay on the legacy path.
- **Slice 4 — prompt shape is compared before sampling.** Status: blocked on
  slice 3. Run matched, blinded generations for the current lane default, the
  existing `concise_immersive` shape and the new immersive profile. Judge scene
  presence, voice, beat resolution, state obedience, player agency, neutral-scene
  restraint, repetition, latency and context failures. Length is recorded but is
  never a quality score by itself.
- **Slice 5 — finalists earn exact-model call settings.** Status: blocked on
  slice 4. Start with temperature as the only sampling variable. Add another
  decoding or provider option only after a live capability probe proves both
  narrator call paths accept it. Every winning setting is keyed to one full model
  id and one narrator lane; the established cohort remains untouched.
- **Slice 6 — qualified profiles enter the successor renderer.** Status: blocked
  on slices 4–5. Test one candidate at a time against the successor's strict JSON
  contract, committed-cut audit, hidden retry and solo fallback. A profile enters
  this lane only after it preserves required beats, handle isolation, state truth
  and player agency. The model-selection wiring itself lands earlier in slice 2;
  this slice decides which non-legacy craft and sampling settings may follow it.
- **Slice 7 — the full bench produces a default ruling.** Status: blocked on
  slices 4–6. Run the surviving configurations over the full fixture set and a
  long-history pass. Either promote an exact model plus its exact narrator
  profile, or record that the incumbents held. Remove rows that cannot follow the
  contracts, overflow their usable context, or add no useful cost/quality lane.

## Success criteria

The build is successful when all of the following are true:

- Representative prompt and call-option fixtures for Aion 3.0, DeepSeek 4 Flash
  and GLM 5.2 are byte-identical before and after the profile seam. The same
  regression protection covers the other unprofiled established models.
- Selecting Magnum, Euryale or another opted-in narration model changes only the
  narrator's effective presentation profile, never a composer, state agent,
  intake leg, post-turn leg, image model or simulation deliberator.
- The immersive profile produces a clearly preferred scene on the fixed
  comparison set without a worse rate of state contradictions, player-agency
  violations, refusals, attribution failures or unsolicited plot movement.
- Richer replies come from reaction, voice, physical behavior and permitted
  scene texture rather than repeated facts, inflated summaries or invented
  subplots.
- A successor chat honors the same narrator choice the ordinary route would use,
  records the effective model/profile, and still falls back to Aion 3.0 when no
  choice exists.
- Every promoted sampling setting can be reproduced from one recorded model id,
  lane, prompt profile and call profile. No model family inherits settings by
  name resemblance.
- A 32K candidate either completes the long-history fixture without overflow or
  remains explicitly non-promotable until context fitting is designed and
  accepted.

## Open questions

- **Can a narrator that thinks before it speaks work in the chat lane at all?**
  The first Featherless row spends about a minute of hidden reasoning before its
  first visible word, and the chat lane gives up on a silent reply after fifty
  seconds — a ceiling set by the hosting proxy, not by preference, so it cannot
  simply be raised. The choices are to suppress the model's thinking if the
  provider allows it, to confine thinking narrators to a surface without that
  ceiling, or to drop the row. Nothing else in the second-provider work depends
  on the answer ([detail](narrator-model-bench.spec.md)).
- **Which roleplay candidates actually earn `immersive_roleplay`?** The initial
  exact-model cohort is a hypothesis; slice 4 decides the durable map
  ([detail](narrator-model-bench.spec.md)).
- **Which finalists need sampling changes after prompt shape is corrected?** The
  answer controls whether slice 5 adds any per-model setting at all
  ([detail](narrator-model-bench.spec.md)).
- **Which candidate profiles can survive the successor's structured contract?**
  A strong free-prose narrator may still be unsuitable for the committed-cut
  renderer ([detail](narrator-model-bench.spec.md)).
- **Does the speaker-tag renderer survive the bench?** A model that insists on
  asterisk-action roleplay syntax may need to be dropped rather than broadening
  the output grammar ([detail](narrator-model-bench.spec.md)).
- **Does a 32K context window bind under richer replies?** The long-history pass
  decides whether those rows remain test-only or need a separate context-fit plan
  ([detail](narrator-model-bench.spec.md)).
