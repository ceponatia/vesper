# developer-notes folder instructions

This folder contains plan and spec files for development phases. Whenever possible, keep these documents up-to-date. When we develop something that conflicts with planned work, please update the planned work to reflect what has changed.
If a complete reanalysis and rewrite of the planned work is needed due to other changes in code, say so in the relevant document. Do not do this analysis unless asked to, but tell the user in your response that it is needed.

## gpt-review

This folder contains reviews of plan and spec documents in the root developer-notes folder written by GPT-5.5-XHIGH.

- When reading plan and spec docs, it will be noted in those files if the gpt-review docs have already been taken into account. If they have, you do not need to re-read those files. If they have not, please read the files related to the plan and scope documents you are working with and incorporate their feedback as you see fit.
- Use your judgment when doing so. If you disagree with GPT's feedback, please say so in the relevant area of the document so we can look at going a different way.

## user-guidance

This folder is similar to the gpt-review folder except it is written by the user. As such, the desires and intent in these documents have a higher precedent than other notes. You may tell the user when you disagree with an idea or plan, or if you have better ideas.

- The `ideas.md` document is a raw list of development ideas that have not been fleshed out. Further instructions about that document are in the file.
