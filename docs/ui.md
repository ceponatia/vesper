# UI

Next.js App Router pages + React 19 + Tailwind 4. Aesthetic: quiet dark "reading room" — ink background, warm paper accents, serif narrative type (`Source Serif 4` or similar variable font), sans UI chrome. Design tokens in `globals.css` `@theme`; no component library — small owned primitives in `src/components/ui/`.

The global header (`components/shell/app-shell.tsx`) links **Chats · Worlds · Characters · Locations · Items · Social cards · Gallery** at ≥md; on phones a bottom tab bar or hamburger drawer takes over (see **Mobile**). A session is started from a world's **Begin session** or the dashboard (there is no navbar "New session" button — it was removed as redundant). The Gallery is a separate page; scene images never appear on the landing dashboard.

The world review/editor map tab (`components/worlds/world-editor.tsx`) renders each location as a collapsible card — the header is a real button (`aria-expanded`, caret) showing name, tags, and a scale/area hint; multiple cards can be open at once, existing cards load collapsed, and new/copied cards open expanded. Cards reorder by native HTML5 drag (grip handle, drop-indicator line) with per-card move up/down buttons as the keyboard-accessible path; the order is authored data, written as the array index to `world_locations.sort` on save and read back ordered everywhere (detail, edit, spawn). A per-card Copy duplicates the place itself (description, tags, scale, area, ambient) but not the name (left empty — duplicates break save resolution), links, or the library/world row references. Links are undirected at runtime, so each card also lists incoming connections added on other locations as read-only text, and adding a link whose reverse already exists is refused with a brief inline note instead of creating a doubled edge.

The read-only world **detail** page (`components/worlds/world-detail-page.tsx`) shows the same sections; its **Map** section is **collapsible and collapsed by default** (production worlds have many locations). Expanded, it renders a **read-only force-directed graph** (`components/worlds/world-map-graph.tsx`, laid out by the pure deterministic `lib/world-graph-layout.ts`) — locations as nodes, undirected links as edges, so adjacency reads at a glance and a **disconnected location shows in danger-red** (the audit-M2 motivation); the flat card list (descriptions + adjacency) is preserved under a `<details>` "Location list" disclosure for accessibility/detail ([developer-notes/world-map.plan.md](developer-notes/world-map.plan.md) Slice 1). On phones the list renders directly in place of the disclosure (the scaled-to-width graph is cramped, so the touch-friendly list is the primary view — see **Mobile**). While a world-image backfill is still running (`getWorldDetail` returns `imageJobActive` — an active `entity_image`/`world_backfill` job for the world), the page shows a subtle **"Generating artwork… (n/total avatars)"** badge, swaps the world image + missing cast avatars for shimmer skeletons, and polls until the job clears — so a freshly-saved world no longer reads as bare monograms with no hint art is coming (UX-audit M7).

The world review/editor cast tab (`components/worlds/world-editor.tsx`) carries per-member relationship rows — a `toward` select (other cast names + "player", with a "(missing)" option keeping unresolved names visible) and a stage select fed by the `contracts/relationships/stages` registry (stages, never numbers), with add/remove affordances. Renaming a cast member rewrites other members' `toward` pointers, the same way map renames follow location links. When the cast would spawn more than `MAJOR_TIER_SOFT_CAP` (6) major-tier members, the tab shows a non-blocking warn-toned notice — the count uses `lib/cast-tiers.ts` (the same rule `engine/spawn.ts` applies: companions left at the default minor tier spawn as major), and spawn emits the matching `spawn.cast.major_soft_cap` diagnostic; nothing is ever blocked or trimmed. Scale and tier select options are derived from the contract enums in `lib/client/api.ts` (`worldLocationScaleSchema` / `worldCastTierSchema`), not inline literals.

The character portrait studio (`components/characters/portrait-studio.tsx`) generates the canonical avatar from attributes, accumulates Venice pose/outfit/expression/setting variants, and promotes any variant to canonical. Its **Portrait history** grid keeps non-canonical avatar attempts and variants visible; failed rows render as error cards using `images.meta.error` so provider failures do not vanish after polling. **Upload image** opens the crop dialog (`avatar-upload-dialog.tsx`): a modal whose helper text states the 768×1024 (3:4) target, then — unless the chosen file is already 3:4 — lets the user drag to reposition and a slider/scroll to zoom inside a 3:4 crop window before the framed region is scaled, saved, and set as the avatar (synchronous, demo-safe — [images.md](images.md) §Avatar upload).

The library **item** and **location** editors are split into **Details · Image** tabs (`components/ui/tabs.tsx`). The Image tab is a minimal studio (`components/library/entity-image-studio.tsx`, shared by both): a Generate/Regenerate button and the current image with click-to-enlarge — no variants, no upload (regenerate if you dislike it). Generation runs as a background job and the tab polls until it lands, so leaving the page never interrupts it. Items get a 1:1 product photo; locations a 3:2 establishing shot whose type follows the location's scale ([images.md](images.md) §Entity images). Every lean library editor (items, locations, social cards — every branch, including loading/error) opens with a **`← <Library>` back link** (`components/library/back-link.tsx`, `.touch-target` on phones) returning to its grid — the mobile escape hatch; the grid restores the toolbar state the user left (below).

The library **location** editor's Details tab carries the full location design (parity with the world map tab): **Scale**, **Area**, and a **Connections** section — undirected links to other library locations added through the shared `EntityPickerDialog` (search + thumbnails), shown as removable tags. Connections persist as `location_links` and propagate into a world's map when the linked set is imported ([database.md](database.md), [images.md](images.md) §Entity images). A location's scale also drives its generated image (landscape vs interior).

The shared library grid (`components/library/entity-library.tsx`) is config-driven per entity; the **Items** library is the full faceted browse ([library-ux.plan.md](developer-notes/library-ux.plan.md)):

- Segmented **Clothing · Object · Container** buckets (live counts; no "All" — the page opens straight into Clothing, the closet view), then **registry-backed facet chip rows** that adapt to the bucket — clothing gets category / wearer / layer chips + color **swatches**, objects get subtype chips (`components/library/item-facets.ts`; wearer follows `wearerMatchesFilter`, so absent/unisex garments match every wearer chip). Facets filter the loaded set client-side with counts scoped to the other active filters; options absent from the data are hidden. Switching buckets clears facet picks.
- With nothing narrowing, the grid renders **grouped sections** — Clothing → by category (the "closet" view), Object → by subtype; any search/tag/facet goes flat. A single section renders flat too (one group is noise, not organization). (The `buckets.defaultId` config also suppresses "All" and sets the initial bucket — items is the only entity currently using it; social-cards still opens on "All".)
- A **grid ⇄ list toggle** (persisted per entity in localStorage) swaps the rich cards for compact rows — small thumb, name, structured chips (category/subtype + color dot), tags — for hundreds-of-items scale; plus a **sort** select (Recent first / By name, applied server-side).
- The rest of the toolbar state (bucket, scope, sort, search, tags, facet picks) persists **per entity in sessionStorage**, restored through the lazy state initializers on mount — so opening an editor and coming back (its back link, the nav, or browser back) lands on the same view. Stored buckets/facet options no longer in the vocabulary are dropped at read time (a stale pick would silently empty the grid), and **New** creates in the active bucket — a blank clothing item from the Clothing view, a taboo card from the Taboo tab (`config.create` receives the bucket; "All" falls back to the schema default).
- Free tags moved behind a **Tags** panel: multi-select chips (comma-joined into the `tag` param, ANDed server-side via jsonb containment), with a filter input past 15 tags. **Machine tags** (`suggested`, `seed:*`) are hidden from every filter UI and card chip row (`lib/tags.ts`); the data keeps them.
- **Generate images** (Items/Locations) is unchanged: ids visible under the active filter that lack an image → confirm dialog → background batch, grid polls, hidden on an empty library (UX-audit P3). Items adds **Organize** beside it — the facet classify backfill: visible items missing a facet go to `POST /api/items/classify`, a background `item_classify` job fills **only absent** category/layer/wearer/color/subtype fields from name+description via a cheap model (`server/api/item-classify.ts`), and the grid polls as chunks land. Present values are never overwritten, so it's always safe to press again.

Server-side, the items list API takes the same facets as query params (`category`/`subtype`/`layer`/`wearer`/`color`, plus `sort` and comma-ANDed `tag`) — applied **before** the result cap in `searchLibraryIds` (the defaultOutfit truncation lesson), which is what the pickers lean on. List endpoints select explicit columns (the bare rows used to ship the 1536-dim search embedding to the browser).

**Pickers** (`components/library/entity-picker.tsx`, replacing the old `library-picker`): `EntityPickerDialog` is the one search-and-pick surface behind every "add from library" flow — debounced server search, thumbnails, per-row structured chips, optional **facet chip rows** that re-query, a **grouped empty-query browse** (clothing by category), and a **multi-select basket mode** (pick several, confirm once). Call sites: the character **outfit tab** (below), location connections, world-editor cast add/link and item placement, and the social-card import. The **new-chat dialog** and **session wizard** keep their bespoke avatar/card grids but their filter inputs now re-query the server (`q`) instead of narrowing the capped first page — the wizard's world and play-as steps gained search inputs (`components/hooks/use-debounced-value.ts`).

The character **outfit tab** (`components/characters/outfit-editor.tsx`) reads as wardrobe **slots** — Tops & dresses · Bottoms · Underwear · Footwear · Accessories (`lib/clothing-slots.ts`, a pure category→slot map; unresolved/uncategorized references land in "Other") — each slot's **+ Add** opening the EntityPicker pre-filtered to that slot's categories **and the character's wearer target** (from `identity.gender` via `wearerHintForGender`; always overridable in the picker's facet chips), so a long clothing library arrives as "the tops that fit her". Empty slots read "Nothing worn." A trailing "+ Add from the whole wardrobe…" opens the unscoped picker.

## The play screen

Three regions:

1. **Feed** (center): narrator prose (serif, `*italic*`/`**bold**` inline rendering, no markdown lib — a line that is solely a `*Name: …*` comms span renders as an SMS-style **texted line** (name label + italic body, sigils hidden), the same treatment the chat lane gives it; dialogue-attribution, via the shared `commsLine`/`CommsBody`) interleaved with character bubbles (avatar, name) and player messages (right-aligned). Streaming segments render live by `segmentIndex`. Hover actions per turn: edit / delete / rerun. Scroll pinning: *pinned* means the viewport bottom is within ~80px of the feed bottom; while pinned, new content auto-scrolls. When unpinned (reader scrolled up), new turns **append to the loaded range without refetching or moving the viewport**, and the "Jump to latest" pill appears — the reader is never yanked. The one exception: sending your own message re-pins (the echo appearing is the submit signal), so the reply always streams in view. Older history loads via the `?before` cursor; completing a turn never resets the cursor.
2. **Composer** (bottom): input with author mode — *player* (speak/act), *director* (out-of-world instruction), *companion* (pick an NPC to take the turn), plus an explicit **Send** button (Enter also sends; Shift+Enter is a newline). The textarea is **never disabled** — the player keeps typing while the narrator/agents run; a subtle status line shows the pipeline state. Sending while the session is `narrating`/`processing` **queues** the turn (one slot) and clears the box, showing a "Queued" chip with a cancel ×; the queued turn dispatches automatically the moment the session goes ready. While a turn is queued the Send button is disabled (relabeled **Queue** while busy) until it enters the pipeline, but typing the next turn stays allowed. A failed submit gives the words back only if the box is still empty.
3. **Side panel** (right, tabbed; at ≥`lg` it's a fixed column, below `lg` it slides in as a right-edge `Sheet` via the "World" FAB — see **Mobile**):
   - **Scene**: a **standing companion portrait** at the top (`components/play/session-avatar.tsx`) — a larger view of the focal present NPC's canonical avatar (companion → tier → id; `selectFocalParticipant`), rendered by the shared `AvatarPanel`. Display-only — the mood-reactive expression pipeline was rolled back (developer-notes/avatar-3d.plan.md). Then the current scene image, gallery, generate-now, interval control, and a **References** toggle (one-character ↔ multi-reference — `SceneGenState.referenceMode`; `multi` feeds every present character's avatar + the location image to Venice `/image/multi-edit`, see [images.md](images.md)). Clicking the image opens `ImageLightbox` (`ui/image-lightbox.tsx`, also used by the portrait studio and the character-chat scene strip): full-screen enlarged view over a darkened backdrop, Escape/backdrop-click to close. When a caller passes the image's generation `prompt`, an **admin-only "Generation prompt" side panel** renders beside the image for dev troubleshooting — gated by `useIsAdmin` (`components/hooks/use-is-admin.ts`, a module-cached `/api/dev/me` role check, the same gate as the Inspector tab); normal users never see it, and the lightbox owns the gating so callers pass the prompt freely. Below the controls, a **"Here with you"** section lists the NPCs co-located with the player (the present set the scene composer draws from; the player is excluded) using the same `ParticipantCard` as the Cast tab (extracted to `components/play/participant-card.tsx`, shared by both) with its own accordion — a quick read on who is here to interact with. Co-location follows `composer.tsx`'s rule (filter by `locationId` when known, include otherwise).
   - **Cast**: per-participant accordion cards — the header is a real button (`aria-expanded`); clicking expands the card in place, clicking again collapses it, and at most one card is expanded at a time. Collapsed: portrait, activity, a **mood chip** for non-player cards (a glyph + the derived `EmotionLabel` — `StatusParticipant.emotion` from `deriveEmotionLabel`, the sustained baseline face, no reaction beat; see [contracts/meters-actions.md](contracts/meters-actions.md) §Mood and developer-notes/mood.spec.md), tier chip (major/minor/extra, from the status payload), meters (compact bars), active conditions, visible outfit. Expanded adds the full inventory — every worn layer from the payload's `wornFull` list with hidden-under-other-layers items marked as such (`wardrobe` keeps its visibility-filtered semantics) — **dev-only display**: before production the expanded list must filter hidden layers so players can't see under-layers the fiction hides (UI-only change; the shared visibility resolution and state are unaffected — followups.phase2.md #7) — plus held items, the remaining time on timed conditions, and the character's current location when they're not co-located with the player. Admins in non-production builds also get wardrobe test controls on the Cast tab: remove a worn garment into that character's held inventory, or wear a held clothing item again; the route is refused while a turn is processing so it cannot race the merge. Expanded non-player cards also carry an **Inner note** section: a compact textarea (placeholder spells out the contract — inject a memory, feeling, or belief, never dialogue or actions) and submit button, disabled while submitting; accepted notes toast "«Name» will carry this from the next turn" (processing is a non-blocking background job — [turn-engine.md](turn-engine.md) §Jobs, [memory.md](memory.md) §Authored interior facts), errors toast the API message. Non-player cards show the NPC's relationship stage toward the player ("Friendly toward you", from `/relationships`; no edge reads as Stranger) plus what the NPC believes the player feels ("thinks you're friendly toward them") — the perceived line is hidden while the pair is mutually stranger (feeling stage stranger and perceived edge absent-or-stranger, where it carries no information); once either side shows a non-stranger signal both lines render, a missing perceived row displaying as "stranger" (`components/play/cast-relationship.ts`). Stage labels come from the `contracts/relationships/stages` registry; raw affinity values are never shown.
   - **World**: game clock with the latest turn's advance beside it ("+20m — Shower"; the generic "scene" cause renders as just "+20m", old turns without a delta render nothing), current location + the loose items / open containers there (from the status payload's **top-level `items`** list filtered to the current location — that list was previously missing, so "Items here" always read "Nothing of note" regardless of placement; UX-audit P6), narrator model dropdown (options from the shared curated list in `lib/narrative-models.ts` — the same source the server's resolver defaults from; writes the world's `narrativeModel` via world PATCH; `/status` reports the resolved id, and an id outside the list renders as-is), an **agent model dropdown** ("Agents (non-narrator)", options from `lib/agent-models.ts`; writes the world's `agentModel` via world PATCH; switches the **in-session** intake + post-turn agents only — never the narrator, the world/character authoring agents, or the image pipeline), and **open story threads** — each a clickable card (title, kind/cooling tags, 2-line summary) that opens the thread detail modal (`components/play/thread-modal.tsx`, on the shared `Dialog`): question, rolling summary, "what would close this" (investigations), and the full developments timeline. Admins get a confirm-gated **"Close thread"** control there that resolves the thread (it then drops from the World tab). See [story-threads.md](story-threads.md).
   - **Inspector** (dev users only): a per-turn **Turn** line (model, token usage from the inspect payload's `turn.usage`, clock advance, and an **intake: LLM / regex fallback** indicator derived from the persisted `agent.intake.timeout` diagnostic — step through turns to gauge the intake fallback hit-rate before tuning its budget, UX-audit M5), then agent results, diagnostics, and retrieval scores.

## The conversation page

`/chat/:chatId` (`components/chat/chat-conversation.tsx`, [character-chat.md](character-chat.md)) is the character-chat analogue of the play screen: a mobile-first single column filling `calc(100dvh - 3.25rem)` (the app-header height — see the app-shell.tsx comment), transcript scrolling internally, composer pinned to the bottom edge with iOS safe-area padding (the bottom tab bar is suppressed on this route, same rule as `/sessions/…`). It is **chatId-driven — the conversation always exists** (created from the Chats hub / New-conversation dialog); there is no lazy create. One `GET /api/chats/:chatId` envelope settles the screen: transcript + chat header (title, archived) + character card (name, `avatarImageId`, `chatModel`). The pieces:

- **Header row**: back link to `/chat`, small portrait (tap → the portrait lightbox), character name + chat title (auto-title = the character's name when the title is empty), and a **menu** — a bottom `Sheet` under md, an AccountMenu-style popover at ≥md — holding the **narrator model** select (same curated list + serialized save-on-pick as the editor tab), **Scenario setup**, **Relationship** (opens the panel below), **State tools**, an **Inspector** item (admins only — navigates to `/chat/:chatId/inspector`, the memory inspector; its `/api/admin/chat-inspector` family is role-gated server-side so it works on the deployed build, [character-chat.md](character-chat.md) §API), a **"Let time pass"** chip row (Moments/Hours/Overnight/Days → `POST …/time-skip`, hidden on archived chats), **Rename** (PATCH `title`), **Archive/Restore**, and **Delete chat…** (confirm dialog → hard delete → back to `/chat`).
- **Scene images**: a collapsible section under the header holding the scene strip, **collapsed by default at every width** — the toggle is remembered in component state only, and the section heading lives on the disclosure toggle (the strip's own header row is just the Generate button). The conversation page owns **one** scene fetch/poll shared by the strip and the inline transcript moments; `SceneStrip` is presentational over that list (it renders + queues, never fetches). The poll arms while the GET's **`rendering`** flag is true (a live `chat_scene_image` job) **or** a pending row exists — the flag is what covers the slow composer step before the pending image row lands, so a queued render's "Painting…" tile resolves live instead of sitting until a manual refresh (and an auto-queued or mid-compose-refreshed render still shows the tile, via `rendering`, with no local click state).
- **Standing portrait**: at ≥`lg` the character's `AvatarPanel` portrait sits in a fixed column to the **left of the transcript** (using the desktop side real estate; `w-52`, `w-64` at ≥`xl`), clickable to enlarge. Below `lg` the column is hidden entirely — phones reach the full-size portrait by tapping the **header portrait** or any reply's **circular avatar** (`MessageBubble`'s optional `onEnlargeAvatar`, passed only when an avatar image exists). All three affordances open the **same** shared `ImageLightbox`, one instance at the page level.
- **Transcript**: the same `MessageBubble` hover actions as before — **Edit** / **Delete** (poisoned-window recovery levers; both now also reconcile the line's extracted memory, [character-chat.md](character-chat.md) §Post-turn fan-out), **Rerun** on the user's own lines (re-sends that prompt, dropping everything after it and cancelling any in-flight reply; the server still drains/persists the cancelled reply and the transcript reload reconciles), and **Remember** (opens the "Remember this" dialog prefilled with that line — a pinned player fact, [memory.md](memory.md) §Pinned facts). Since slice 5: **Another take** on the last settled reply (streams the regeneration into the same bubble in place — state rolls back to the pre-exchange snapshot and the old take's memory is retracted server-side), a **takes pager** (`‹ 2/3 ›`) in the footer of any reply with recorded takes (switching is display-only — state/memory reflect the last *generated* take), and a subtle **stopped** chip on replies the player cut short. Since slice 9: ready scenes anchored to a message render as **inline scene moments** — a thumbnail row (`SceneMomentRow`, shared lightbox) under the line they illustrate; un-anchored/dangling-anchor scenes stay strip-only. Message bodies on **both** sides render through the **markup span renderer** (`components/characters/message-content.tsx` over the pure, unit-tested `message-markup.ts`, which reuses `lib/message-spans` — no second parser; [developer-notes/player-input-perception.plan.md](developer-notes/player-input-perception.plan.md) slice 5): `*thoughts*` and `_italic_` show italic with the sigils hidden, `*Name: …*` comms read as a text message (the `Name:` label kept, the body italic), and `((OOC))` gets an out-of-fiction amber aside (parens hidden) — speech (quotes kept) and narration render exactly as before, blank-line paragraph breaks survive, and an unterminated sigil mid-stream stays literal until it closes. Because the outermost sigil wins, a `_…_` pair nested **inside** a span body (most commonly quoted speech — `"it's _perfect_!"`) never becomes its own span; every piece body therefore also flows through `parseEmphasisRuns` (`lib/message-spans`, unit-tested), which italicizes the run with the underscores hidden (and flips it upright inside an already-italic body — thought/comms/OOC — standard nested-emphasis typography). The exported transcript keeps the **raw** sigils (markdown-compatible). Narrator/character replies (not the player's own bubbles) additionally render as **in-bubble per-speaker segments** (dialogue-attribution — `chat-segments.ts` over `lib/segmenter`, unit-tested): the `[Name]` tag is hidden behind a small accent speaker label (mirroring the feed's), and in this one-on-one an untagged **whole-line quote** attributes to the character just like a tag would — segments stay INSIDE the one reply bubble (the chat lane is "a story being told", not separate bubbles), segment content still flows through the span renderer, and a segment that is solely a `*Name: …*` comms line keeps its comms label rather than doubling it. Re-parsing the growing reply each streaming render is cheap (the parser is pure) and the unterminated tail stays stable. The transcript's auto-scroll is **stick-to-bottom**: it pins on new lines only while the reader is already at the bottom (scrolling up to reread stops the yanking), and a `ResizeObserver` on the content column re-pins as async content (scene thumbnails, avatars) grows it after load — without that, the initial view landed mid-transcript once images finished, hiding the newest exchange below the fold. A stream that settles cleanly but delivered **zero tokens** (the server's first-token watchdog tripping on a stalled provider — no reply row persists) surfaces an explicit error toast ("<name> didn't reply") instead of the pending bubble silently vanishing.
- **Bottom cluster**: a slim scenario-premise line (tap → Scenario setup), the status strip (mood chip + affinity stage chip + off-baseline meter pips), a dismissable **"Pick up:" strip** on reopen (`ChatPickupStrip` — Continue is the no-op default; Later / Next morning / Days later fire a time skip), the one-tap **"Let _name_ speak" banner** when the page opened via a `?say=1` marker tap (sends a `continue` beat cued to exactly that open loop, the param stripped after read), the **Prompt _name_** opening-beat button (empty transcript only) and a quiet **Go on →** (idle, last line an assistant reply — a `continue` beat: no user bubble, the pulse is skipped, the archivist still remembers it), test-bed **action chips**, then the composer (Enter sends, Shift+Enter newline; a **bookmark button** opens the same "Remember this" dialog empty; **Stop** swaps in for Send while a reply streams — what already streamed persists as the reply). A stage-change toast fires when the affinity stage moves. The composer carries an **OOC assist** (player-input-perception slice 5): typing `((` auto-inserts the closing `))` with the caret left between them (Backspace on the empty pair removes both rather than stranding the `))`; skipped when `))` already follows, and paste is untouched — only a literal `(` keypress triggers it), and while the caret sits inside a `((…))` block the textarea tints amber with an **OOC** badge cueing that it's a note to the storyteller no one in the scene hears. Caret placement after the auto-insert is deferred to the next animation frame (the controlled-textarea pattern); the in-block check is a cheap bracket-balance probe (`caretInOocBlock`), since the parser is offset-free.
- **Relationship panel** (`components/chat/chat-relationship-panel.tsx`, in the shared `Sheet`): stage + affinity, the history **sparkline**, **milestones** (glyph-badged by kind, newest first), unfinished business (open loops), the **story so far** (rolling summary) with a **Rebuild from full transcript** lever (`POST …/summary/rebuild`), and **Export** download links (md/json, with a memory-appendix checkbox). One `GET …/relationship` settles it.
- **Archived** conversations render read-only: a slim "Archived — restore to continue" banner with an inline Restore, composer/chips disabled (the server also 409s `chat_archived`).

The **Scenario setup** modal carries the scenario-preset loop (spec §1.5): an **Apply preset** select (fills the draft; Save persists) with per-preset delete, and **Save as preset…** capturing the current premise/outfit/cards, plus the **"Auto-generate a scene at big moments"** toggle (writes `sceneAuto` `"off"|"milestones"` — [images.md](images.md) §Scene images); the **New-conversation dialog** offers **Start from preset**, seeded server-side at create.

The editor's Chat tab links here rather than embedding any of this (see `/characters/:id` above).

## Mobile

One responsive component tree (no separate mobile build); CSS breakpoints reflow the layout and a few JS hooks switch behaviour. There is **no user-agent sniffing** — "mobile" is screen width: `useIsMobile()` (`components/hooks/use-is-mobile.ts`, `matchMedia("(max-width: 767.98px)")`, one hair under Tailwind `md`/768) drives behaviour, `md:`/`lg:` utilities drive layout. The root layout exports a `viewport` with `viewportFit: "cover"`; the bottom bar and play composer reclaim the iOS safe area with `env(safe-area-inset-bottom)`.

**Primary nav** (`app-shell.tsx`): at ≥md the horizontal top-nav shows. Below md it swaps to one of two chromes chosen by a persisted **nav-mode** (`lib/nav-mode.ts`, default `tabs`): a fixed **bottom tab bar** (`bottom-tab-bar.tsx` — Home · Chats · Characters · Worlds + a **More** bottom-sheet holding Gallery/Locations/Items/Social cards and the nav-style switch; Chats holds a primary slot per D12) or a **hamburger + left drawer** (`nav-drawer.tsx`). `NavMode` is a two-value union, so exactly one chrome ever renders — "both" and "neither" are unrepresentable; the switch (`nav-mode-toggle.tsx`) lives in both the More sheet and the drawer footer so you can always flip out of the current mode. The bottom bar is **suppressed on the immersive surfaces** (`/sessions/…` and `/chat/:chatId` — not the `/chat` hub) so its fixed footer never collides with the composer; the hamburger lives in the header and stays available everywhere.

**Sheet** (`components/ui/sheet.tsx`): an edge-anchored modal (`side` = right/left/bottom) that shares Dialog's overlay-click/Escape/focus-trap via the extracted `components/ui/use-focus-trap.ts` (Dialog uses it too). The trap focuses the panel **only on the open transition** (its own effect, keyed on `open` alone, skipped when focus is already inside — so an `autoFocus` child wins): callers pass inline `onClose` functions, and an effect that depended on `onClose` *and* called `focus()` re-ran on every parent render, yanking focus out of the input being typed in (one keystroke per click — the new-chat title bug). It backs the nav drawer, the More overflow, and the play **side panel** (right-edge, under `lg`, via the "World" FAB — replacing the old hand-rolled drawer). Its `fixed inset-0` overlay is **portalled to `document.body`** (via `createPortal`): the nav drawer mounts inside the `backdrop-blur` header, and a `backdrop-filter`/`transform`/`filter` ancestor establishes a containing block for `position: fixed` descendants — without the portal the overlay collapsed to the header's height and the drawer body (links + the nav-mode switch) was clipped to a sliver, leaving an apparently-empty hamburger with no way back to the bottom bar. `document.body` is always a clean viewport-sized containing block.

**Touch** (all in `globals.css` under `@media (pointer: coarse)` / `(hover: hover)`): small controls opt into a ≥44px tap height with `.touch-target`; reveal-on-hover action clusters use `.hover-reveal` (always visible on touch, hover-gated only where hover exists — e.g. portrait-studio variant actions); form fields are pinned to 16px on coarse pointers so focusing them never triggers iOS zoom. The dense `Tabs` strip (the 5-tab world / 7-tab character editors) scrolls horizontally and keeps the active tab scrolled into view.

## Conventions

- Server components fetch; client components interact. Data flows in through route handlers already shaped for the view (no client-side joins).
- Client data layer: plain `fetch` + small hooks (`useSessionStatus`, `useTurnStream`); no react-query unless pain demands it.
- Every async surface has a skeleton + error state; images always have the monogram fallback; missing/legacy data renders as absent, not broken ([resilience.md](resilience.md) §7).
- Secondary-text tokens must clear **WCAG AA** on the dark surfaces they sit on: the faint `--color-paper-500` is the AA floor (≥4.5:1 on `ink-800` cards and `ink-700` raised surfaces) — don't reintroduce a dimmer body-text grey (UX-audit M6). On top of that floor, an **opt-in high-contrast theme** (header toggle, `components/shell/contrast-toggle.tsx`) sets `data-contrast="high"` on `<html>`, which `globals.css` keys a `:root[data-contrast="high"]` block off to lift the quiet `paper`/`ink` tokens further; the choice persists in `localStorage` and is applied **pre-paint** by an inline script in the root layout (no flash). The pure read/parse/apply path is `lib/contrast-theme.ts` (UX-audit §4 / feature #6).
- Forms: controlled state + zod validation on submit; shared `Field` primitives; sticky save bar with dirty-state indication on long editors (the old `EditPageChrome` pattern, rebuilt). Editor drafts seed from fetched data **exactly once per entity** (`components/hooks/draft-seed.ts`, applied during render): refetches and silent reloads never clobber in-progress edits, and navigating between entities drops the stale draft until the new one loads. The chat conversation page seeds its transcript/header the same way (a chatId switch clears the previous chat's lines immediately instead of letting them linger until the new fetch lands).
- Background-job surfaces poll while pending through `usePollWhile(active, tick, ms, { maxPolls? })` (`components/hooks/use-poll-while.ts`) — the tick is latest-ref'd so a fresh closure never restarts the interval, and `maxPolls` is the safety cap (e.g. the world detail page's ~5-minute backfill poll). Don't hand-roll `setInterval` poll loops.
- Curated model dropdowns (narrator/agent/chat) render through `ModelSelect` (`components/ui/model-select.tsx`): options come from the shared lists in `lib/narrative-models.ts` / `lib/agent-models.ts`, and a value **outside** the list still renders as its own option (the id as-is) so a legacy/env-override id is never silently swapped.
