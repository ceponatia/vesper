# UI

Next.js App Router pages + React 19 + Tailwind 4. Aesthetic: quiet dark "reading room" — ink background, warm paper accents, serif narrative type (`Source Serif 4` or similar variable font), sans UI chrome. Design tokens in `globals.css` `@theme`; no component library — small owned primitives in `src/components/ui/`.

## Pages

```
/                        Dashboard: conversations lead ("Continue talking to…" — D12; hidden until a chat exists), then continue-session hero, recent worlds, cast strip
/worlds                  Library grid (search/tags)
/worlds/forge            Prose prompt + counts (0–5 locations/characters) → draft review (tabs: premise/map/lore/cast/items; premise tab carries the "Play as" pick) → save
/worlds/:id              Detail: synopsis, cast, map (collapsible, default collapsed), lore, sessions; "Begin session"; "Generating artwork…" hint + shimmer while a backfill runs
/worlds/:id/edit         Same review UI as forge, loaded from saved world
/characters              Library grid
/characters/forge        Prose prompt → draft review → save
/characters/:id          Editor: profile · attributes (registry picker; body-config/features overrides sit at the bottom) · personality (voice/presentation/movement) · outfit · portrait studio · chat (a **summary surface** since the standalone arc — playing happens on /chat/:chatId, see §The conversation page: a **Chat defaults** card — the **narrator model** dropdown (curated `lib/narrative-models.ts` list; picking saves immediately to `characters.chatModel`, serialized against rapid picks, and the value is hoisted to the edit page so it survives tab unmounting) plus the authored **Starting Relationship** stage + one-line note (`profile.playerRelationship`, rides the editor SaveBar) — and a **Conversations** card listing this character's active chats (title-or-auto, `timeAgo` stamp, last-line snippet, each linking to /chat/:id) with a **New conversation** button opening the shared components/chat/new-chat-dialog.tsx)
/chat                    Chats hub: conversation rows (portrait, name/title, snippet, mood + stage chips, relative time), Active/Archived shelves, rename/archive/delete actions, "New conversation" (components/chat/chats-page.tsx; ?new=<characterId> opens the dialog pre-picked — the library-card entry point)
/chat/:chatId            Full-screen conversation (mobile-first; §The conversation page)
/locations, /locations/:id   Lean library + editor (Details · Image tabs)
/items, /items/:id           Lean library + editor (Details · Image tabs)
/gallery                 Scene-image gallery: all generated scenes across still-existing sessions, grouped by session, filterable by world/character; each scene deletable from the grid (hover ✕ → confirm dialog → clean delete from db + session) (components/gallery/gallery-page.tsx)
/sessions/new            Wizard: world → embodiment (play a character / observer; pre-filled from the world's default player, still overridable) → title
/sessions/:id            The play screen
```

The global header (`components/shell/app-shell.tsx`) links **Chats · Worlds · Characters · Locations · Items · Social cards · Gallery** at ≥md; on phones a bottom tab bar or hamburger drawer takes over (see **Mobile**). A session is started from a world's **Begin session** or the dashboard (there is no navbar "New session" button — it was removed as redundant). The Gallery is a separate page; scene images never appear on the landing dashboard.

The world review/editor map tab (`components/worlds/world-editor.tsx`) renders each location as a collapsible card — the header is a real button (`aria-expanded`, caret) showing name, tags, and a scale/area hint; multiple cards can be open at once, existing cards load collapsed, and new/copied cards open expanded. Cards reorder by native HTML5 drag (grip handle, drop-indicator line) with per-card move up/down buttons as the keyboard-accessible path; the order is authored data, written as the array index to `world_locations.sort` on save and read back ordered everywhere (detail, edit, spawn). A per-card Copy duplicates the place itself (description, tags, scale, area, ambient) but not the name (left empty — duplicates break save resolution), links, or the library/world row references. Links are undirected at runtime, so each card also lists incoming connections added on other locations as read-only text, and adding a link whose reverse already exists is refused with a brief inline note instead of creating a doubled edge.

The read-only world **detail** page (`components/worlds/world-detail-page.tsx`) shows the same sections; its **Map** section is **collapsible and collapsed by default** (production worlds have many locations). Expanded, it renders a **read-only force-directed graph** (`components/worlds/world-map-graph.tsx`, laid out by the pure deterministic `lib/world-graph-layout.ts`) — locations as nodes, undirected links as edges, so adjacency reads at a glance and a **disconnected location shows in danger-red** (the audit-M2 motivation); the flat card list (descriptions + adjacency) is preserved under a `<details>` "Location list" disclosure for accessibility/detail ([developer-notes/world-map.plan.md](developer-notes/world-map.plan.md) Slice 1). On phones the list renders directly in place of the disclosure (the scaled-to-width graph is cramped, so the touch-friendly list is the primary view — see **Mobile**). While a world-image backfill is still running (`getWorldDetail` returns `imageJobActive` — an active `entity_image`/`world_backfill` job for the world), the page shows a subtle **"Generating artwork… (n/total avatars)"** badge, swaps the world image + missing cast avatars for shimmer skeletons, and polls until the job clears — so a freshly-saved world no longer reads as bare monograms with no hint art is coming (UX-audit M7).

The world review/editor cast tab (`components/worlds/world-editor.tsx`) carries per-member relationship rows — a `toward` select (other cast names + "player", with a "(missing)" option keeping unresolved names visible) and a stage select fed by the `contracts/relationships/stages` registry (stages, never numbers), with add/remove affordances. Renaming a cast member rewrites other members' `toward` pointers, the same way map renames follow location links. When the cast would spawn more than `MAJOR_TIER_SOFT_CAP` (6) major-tier members, the tab shows a non-blocking warn-toned notice — the count uses `lib/cast-tiers.ts` (the same rule `engine/spawn.ts` applies: companions left at the default minor tier spawn as major), and spawn emits the matching `spawn.cast.major_soft_cap` diagnostic; nothing is ever blocked or trimmed. Scale and tier select options are derived from the contract enums in `lib/client/api.ts` (`worldLocationScaleSchema` / `worldCastTierSchema`), not inline literals.

The character portrait studio (`components/characters/portrait-studio.tsx`) generates the canonical avatar from attributes, accumulates Venice pose/outfit/expression/setting variants, and promotes any variant to canonical. Its **Portrait history** grid keeps non-canonical avatar attempts and variants visible; failed rows render as error cards using `images.meta.error` so provider failures do not vanish after polling. **Upload image** opens the crop dialog (`avatar-upload-dialog.tsx`): a modal whose helper text states the 768×1024 (3:4) target, then — unless the chosen file is already 3:4 — lets the user drag to reposition and a slider/scroll to zoom inside a 3:4 crop window before the framed region is scaled, saved, and set as the avatar (synchronous, demo-safe — [images.md](images.md) §Avatar upload).

The library **item** and **location** editors are split into **Details · Image** tabs (`components/ui/tabs.tsx`). The Image tab is a minimal studio (`components/library/entity-image-studio.tsx`, shared by both): a Generate/Regenerate button and the current image with click-to-enlarge — no variants, no upload (regenerate if you dislike it). Generation runs as a background job and the tab polls until it lands, so leaving the page never interrupts it. Items get a 1:1 product photo; locations a 3:2 establishing shot whose type follows the location's scale ([images.md](images.md) §Entity images).

The library **location** editor's Details tab carries the full location design (parity with the world map tab): **Scale**, **Area**, and a **Connections** section — undirected links to other library locations picked from a dropdown, shown as removable tags. Connections persist as `location_links` and propagate into a world's map when the linked set is imported ([database.md](database.md), [images.md](images.md) §Entity images). A location's scale also drives its generated image (landscape vs interior).

The shared library grid (`components/library/entity-library.tsx`) gains two extras driven by per-entity config. The **Items** library shows a segmented **All · Clothing · Object · Container** bucket filter (each with a live count, shadcn-style segmented control) that filters the grid client-side by `kind`. The **Items** and **Locations** libraries also carry a **Generate images** button beside "New blank": it gathers the ids visible under the active filter that still lack an image, opens a confirm dialog naming how many will be generated (Ok/Cancel), then batch-generates them in the background (images appear as the grid polls). The button covers exactly the selected bucket, so you can fill one type at a time. It is **hidden on an empty library** (nothing to generate — UX-audit P3).

## The play screen

Three regions:

1. **Feed** (center): narrator prose (serif, `*italic*`/`**bold**` inline rendering, no markdown lib) interleaved with character bubbles (avatar, name) and player messages (right-aligned). Streaming segments render live by `segmentIndex`. Hover actions per turn: edit / delete / rerun. Scroll pinning: *pinned* means the viewport bottom is within ~80px of the feed bottom; while pinned, new content auto-scrolls. When unpinned (reader scrolled up), new turns **append to the loaded range without refetching or moving the viewport**, and the "Jump to latest" pill appears — the reader is never yanked. The one exception: sending your own message re-pins (the echo appearing is the submit signal), so the reply always streams in view. Older history loads via the `?before` cursor; completing a turn never resets the cursor.
2. **Composer** (bottom): input with author mode — *player* (speak/act), *director* (out-of-world instruction), *companion* (pick an NPC to take the turn), plus an explicit **Send** button (Enter also sends; Shift+Enter is a newline). The textarea is **never disabled** — the player keeps typing while the narrator/agents run; a subtle status line shows the pipeline state. Sending while the session is `narrating`/`processing` **queues** the turn (one slot) and clears the box, showing a "Queued" chip with a cancel ×; the queued turn dispatches automatically the moment the session goes ready. While a turn is queued the Send button is disabled (relabeled **Queue** while busy) until it enters the pipeline, but typing the next turn stays allowed. A failed submit gives the words back only if the box is still empty.
3. **Side panel** (right, tabbed; at ≥`lg` it's a fixed column, below `lg` it slides in as a right-edge `Sheet` via the "World" FAB — see **Mobile**):
   - **Scene**: a **standing companion portrait** at the top (`components/play/session-avatar.tsx`) — a larger view of the focal present NPC's canonical avatar (companion → tier → id; `selectFocalParticipant`), rendered by the shared `AvatarPanel`. Display-only — the mood-reactive expression pipeline was rolled back (developer-notes/avatar-3d.plan.md). Then the current scene image, gallery, generate-now, interval control, and a **References** toggle (one-character ↔ multi-reference — `SceneGenState.referenceMode`; `multi` feeds every present character's avatar + the location image to Venice `/image/multi-edit`, see [images.md](images.md)). Clicking the image opens `ImageLightbox` (`ui/image-lightbox.tsx`, also used by the portrait studio and the character-chat scene strip): full-screen enlarged view over a darkened backdrop, Escape/backdrop-click to close. When a caller passes the image's generation `prompt`, an **admin-only "Generation prompt" side panel** renders beside the image for dev troubleshooting — gated by `useIsAdmin` (`components/hooks/use-is-admin.ts`, a module-cached `/api/dev/me` role check, the same gate as the Inspector tab); normal users never see it, and the lightbox owns the gating so callers pass the prompt freely. Below the controls, a **"Here with you"** section lists the NPCs co-located with the player (the present set the scene composer draws from; the player is excluded) using the same `ParticipantCard` as the Cast tab (extracted to `components/play/participant-card.tsx`, shared by both) with its own accordion — a quick read on who is here to interact with. Co-location follows `composer.tsx`'s rule (filter by `locationId` when known, include otherwise).
   - **Cast**: per-participant accordion cards — the header is a real button (`aria-expanded`); clicking expands the card in place, clicking again collapses it, and at most one card is expanded at a time. Collapsed: portrait, activity, a **mood chip** for non-player cards (a glyph + the derived `EmotionLabel` — `StatusParticipant.emotion` from `deriveEmotionLabel`, the sustained baseline face, no reaction beat; see [contracts/meters-actions.md](contracts/meters-actions.md) §Mood and developer-notes/mood.spec.md), tier chip (major/minor/extra, from the status payload), meters (compact bars), active conditions, visible outfit. Expanded adds the full inventory — every worn layer from the payload's `wornFull` list with hidden-under-other-layers items marked as such (`wardrobe` keeps its visibility-filtered semantics) — **dev-only display**: before production the expanded list must filter hidden layers so players can't see under-layers the fiction hides (UI-only change; the shared visibility resolution and state are unaffected — followups.phase2.md #7) — plus held items, the remaining time on timed conditions, and the character's current location when they're not co-located with the player. Admins in non-production builds also get wardrobe test controls on the Cast tab: remove a worn garment into that character's held inventory, or wear a held clothing item again; the route is refused while a turn is processing so it cannot race the merge. Expanded non-player cards also carry an **Inner note** section: a compact textarea (placeholder spells out the contract — inject a memory, feeling, or belief, never dialogue or actions) and submit button, disabled while submitting; accepted notes toast "«Name» will carry this from the next turn" (processing is a non-blocking background job — [turn-engine.md](turn-engine.md) §Jobs, [memory.md](memory.md) §Authored interior facts), errors toast the API message. Non-player cards show the NPC's relationship stage toward the player ("Friendly toward you", from `/relationships`; no edge reads as Stranger) plus what the NPC believes the player feels ("thinks you're friendly toward them") — the perceived line is hidden while the pair is mutually stranger (feeling stage stranger and perceived edge absent-or-stranger, where it carries no information); once either side shows a non-stranger signal both lines render, a missing perceived row displaying as "stranger" (`components/play/cast-relationship.ts`). Stage labels come from the `contracts/relationships/stages` registry; raw affinity values are never shown.
   - **World**: game clock with the latest turn's advance beside it ("+20m — Shower"; the generic "scene" cause renders as just "+20m", old turns without a delta render nothing), current location + the loose items / open containers there (from the status payload's **top-level `items`** list filtered to the current location — that list was previously missing, so "Items here" always read "Nothing of note" regardless of placement; UX-audit P6), narrator model dropdown (options from the shared curated list in `lib/narrative-models.ts` — the same source the server's resolver defaults from; writes the world's `narrativeModel` via world PATCH; `/status` reports the resolved id, and an id outside the list renders as-is), an **agent model dropdown** ("Agents (non-narrator)", options from `lib/agent-models.ts`; writes the world's `agentModel` via world PATCH; switches the **in-session** intake + post-turn agents only — never the narrator, the world/character authoring agents, or the image pipeline), and **open story threads** — each a clickable card (title, kind/cooling tags, 2-line summary) that opens the thread detail modal (`components/play/thread-modal.tsx`, on the shared `Dialog`): question, rolling summary, "what would close this" (investigations), and the full developments timeline. Admins get a confirm-gated **"Close thread"** control there that resolves the thread (it then drops from the World tab). See [story-threads.md](story-threads.md).
   - **Inspector** (dev users only): a per-turn **Turn** line (model, token usage from the inspect payload's `turn.usage`, clock advance, and an **intake: LLM / regex fallback** indicator derived from the persisted `agent.intake.timeout` diagnostic — step through turns to gauge the intake fallback hit-rate before tuning its budget, UX-audit M5), then agent results, diagnostics, and retrieval scores.

## The conversation page

`/chat/:chatId` (`components/chat/chat-conversation.tsx`, [character-chat.md](character-chat.md)) is the character-chat analogue of the play screen: a mobile-first single column filling `calc(100dvh - 3.25rem)` (the app-header height — see the app-shell.tsx comment), transcript scrolling internally, composer pinned to the bottom edge with iOS safe-area padding (the bottom tab bar is suppressed on this route, same rule as `/sessions/…`). It is **chatId-driven — the conversation always exists** (created from the Chats hub / New-conversation dialog); there is no lazy create. One `GET /api/chats/:chatId` envelope settles the screen: transcript + chat header (title, archived) + character card (name, `avatarImageId`, `chatModel`). The pieces:

- **Header row**: back link to `/chat`, small portrait, character name + chat title (auto-title = the character's name when the title is empty), and a **menu** — a bottom `Sheet` under md, an AccountMenu-style popover at ≥md — holding the **narrator model** select (same curated list + serialized save-on-pick as the editor tab), **Scenario setup**, **State tools**, **Rename** (PATCH `title`), **Archive/Restore**, and **Delete chat…** (confirm dialog → hard delete → back to `/chat`).
- **Portrait & scenes**: a collapsible section under the header (`AvatarPanel` + the scene strip), collapsed by default on phones — the toggle is remembered in component state only.
- **Transcript**: the same `MessageBubble` hover actions as before — **Edit** / **Delete** (poisoned-window recovery levers) and **Rerun** on the user's own lines (re-sends that prompt, dropping everything after it and cancelling any in-flight reply; the server still drains/persists the cancelled reply and the transcript reload reconciles).
- **Bottom cluster**: a slim scenario-premise line (tap → Scenario setup), the status strip (mood chip + affinity stage chip + off-baseline meter pips), the **Prompt _name_** opening-beat button, test-bed **action chips**, then the composer (Enter sends, Shift+Enter newline). A stage-change toast fires when the affinity stage moves.
- **Archived** conversations render read-only: a slim "Archived — restore to continue" banner with an inline Restore, composer/chips disabled (the server also 409s `chat_archived`).

The editor's Chat tab links here rather than embedding any of this (see `/characters/:id` above).

## Mobile

One responsive component tree (no separate mobile build); CSS breakpoints reflow the layout and a few JS hooks switch behaviour. There is **no user-agent sniffing** — "mobile" is screen width: `useIsMobile()` (`components/hooks/use-is-mobile.ts`, `matchMedia("(max-width: 767.98px)")`, one hair under Tailwind `md`/768) drives behaviour, `md:`/`lg:` utilities drive layout. The root layout exports a `viewport` with `viewportFit: "cover"`; the bottom bar and play composer reclaim the iOS safe area with `env(safe-area-inset-bottom)`.

**Primary nav** (`app-shell.tsx`): at ≥md the horizontal top-nav shows. Below md it swaps to one of two chromes chosen by a persisted **nav-mode** (`lib/nav-mode.ts`, default `tabs`): a fixed **bottom tab bar** (`bottom-tab-bar.tsx` — Home · Chats · Characters · Worlds + a **More** bottom-sheet holding Gallery/Locations/Items/Social cards and the nav-style switch; Chats holds a primary slot per D12) or a **hamburger + left drawer** (`nav-drawer.tsx`). `NavMode` is a two-value union, so exactly one chrome ever renders — "both" and "neither" are unrepresentable; the switch (`nav-mode-toggle.tsx`) lives in both the More sheet and the drawer footer so you can always flip out of the current mode. The bottom bar is **suppressed on the immersive surfaces** (`/sessions/…` and `/chat/:chatId` — not the `/chat` hub) so its fixed footer never collides with the composer; the hamburger lives in the header and stays available everywhere.

**Sheet** (`components/ui/sheet.tsx`): an edge-anchored modal (`side` = right/left/bottom) that shares Dialog's overlay-click/Escape/focus-trap via the extracted `components/ui/use-focus-trap.ts` (Dialog uses it too). It backs the nav drawer, the More overflow, and the play **side panel** (right-edge, under `lg`, via the "World" FAB — replacing the old hand-rolled drawer). Its `fixed inset-0` overlay is **portalled to `document.body`** (via `createPortal`): the nav drawer mounts inside the `backdrop-blur` header, and a `backdrop-filter`/`transform`/`filter` ancestor establishes a containing block for `position: fixed` descendants — without the portal the overlay collapsed to the header's height and the drawer body (links + the nav-mode switch) was clipped to a sliver, leaving an apparently-empty hamburger with no way back to the bottom bar. `document.body` is always a clean viewport-sized containing block.

**Touch** (all in `globals.css` under `@media (pointer: coarse)` / `(hover: hover)`): small controls opt into a ≥44px tap height with `.touch-target`; reveal-on-hover action clusters use `.hover-reveal` (always visible on touch, hover-gated only where hover exists — e.g. portrait-studio variant actions); form fields are pinned to 16px on coarse pointers so focusing them never triggers iOS zoom. The dense `Tabs` strip (the 5-tab world / 7-tab character editors) scrolls horizontally and keeps the active tab scrolled into view.

## Conventions

- Server components fetch; client components interact. Data flows in through route handlers already shaped for the view (no client-side joins).
- Client data layer: plain `fetch` + small hooks (`useSessionStatus`, `useTurnStream`); no react-query unless pain demands it.
- Every async surface has a skeleton + error state; images always have the monogram fallback; missing/legacy data renders as absent, not broken ([resilience.md](resilience.md) §7).
- Secondary-text tokens must clear **WCAG AA** on the dark surfaces they sit on: the faint `--color-paper-500` is the AA floor (≥4.5:1 on `ink-800` cards and `ink-700` raised surfaces) — don't reintroduce a dimmer body-text grey (UX-audit M6). On top of that floor, an **opt-in high-contrast theme** (header toggle, `components/shell/contrast-toggle.tsx`) sets `data-contrast="high"` on `<html>`, which `globals.css` keys a `:root[data-contrast="high"]` block off to lift the quiet `paper`/`ink` tokens further; the choice persists in `localStorage` and is applied **pre-paint** by an inline script in the root layout (no flash). The pure read/parse/apply path is `lib/contrast-theme.ts` (UX-audit §4 / feature #6).
- Forms: controlled state + zod validation on submit; shared `Field` primitives; sticky save bar with dirty-state indication on long editors (the old `EditPageChrome` pattern, rebuilt). Editor drafts seed from fetched data **exactly once per entity** (`components/hooks/draft-seed.ts`, applied during render): refetches and silent reloads never clobber in-progress edits, and navigating between entities drops the stale draft until the new one loads.
